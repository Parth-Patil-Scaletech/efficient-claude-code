Why we're here

We keep running out

Shared seats hit the session or weekly limit, then we borrow each other's, then those run out too.

The fix isn't using Claude less. It's getting the same output for fewer tokens.

Today's target

At least 25% fewer tokens, by following a short list of rules, even without thinking about why.

We recorded the same ticket twice. The rules cut cost by 57%.

The Golden Rules, 5 to 17 min

Ten rules you can follow blindly

  1. One task, one session
  2. Plan before you build
  3. Pick the right model
  4. Point, don't make it search
  5. Keep CLAUDE.md short
  6. Two strikes, then rewind
  7. Facts, not feelings
  8. Trim what you paste
  9. Hand off, don't drag on
  10. No unrequested docs
Rule 1

One task, one session

Before

One session all day: the feature, a git question, yesterday's bug, a thank-you.

After

Task changes, run /clear. Quick unrelated question, ask it in a separate chat.

From our runs: Run A's closing “thanks!” re-read 130k tokens and cost more than any single styling tweak in Run B.
Rule 2

Plan before you build

Before

Paste the ticket. “implement this”. Find out what Claude decided afterwards, then correct it.

After

A short spec with scope, rules and out-of-scope. Plan mode (Shift+Tab), review the plan, then approve.

From our runs: Run A needed 4 rounds of scope corrections. Run B needed none. The spec took a person about 15 minutes.
Rule 3

Pick the right model

Before

Opus for everything, including “commit and push”.

After

Sonnet by default. Opus to plan or debug hard problems. /model opusplan does both. Switch models only right after /clear.

From our runs: switching to Haiku mid-session re-cached the whole 73k context on the new model. It saved almost nothing. The cache belongs to the model.
Rule 4

Point, don't make it search

Before

“Add AI triage to tickets.”

After

“Follow the pattern in @lib/tickets/categorize.ts. Changes go in @lib/tickets/service.ts and @lib/db/schema.ts.”

From our runs: Run B named three files and reused the existing AI client and offline pattern straight away.
Rule 5

Keep CLAUDE.md short

Before

400 lines: onboarding, API docs, history, style essays. Paid for on every message.

After

Commands, hard rules, a pointer to docs/architecture.md, plus guardrails: work only inside this repo, ask before installing anything.

From our runs: Run A left the repo to clean up a file in the home folder and installed a package unasked. Run B's CLAUDE.md fits on one screen and says both.
Rule 6

Two strikes, then rewind

Before

“Still wrong.” “No, try again.” “That's still not it.” Five rounds, each on a bigger context.

After

Corrected the same thing twice? Esc Esc or /rewind to before the bad turn, and rewrite that prompt with the missing detail.

Why: the failed attempts stay in context and keep steering the next answer. Rewinding removes them.
Rule 7

Facts, not feelings

Before (real, from Run A)

“You should be smart enough to realize this. No one is going to find the priority by clicking the details for each ticket.”

After

“Show the priority badge on each ticket card in the list. Leads must be able to change the priority on the detail page.”

From our runs: Run B's tweaks were one sentence each and took two API calls.
Rule 8

Trim what you paste

Before

The whole terminal: 2,000 lines of build output with the error somewhere in the middle.

After

The failing test name and the 10 to 20 error lines. In CLAUDE.md: “When you run tests or builds, report only failures.”

Why: a pasted log isn't paid for once. It's re-sent with every message after it.
Rule 9

Hand off, don't drag on

Before

Backend done, carry on with the UI in the same session, now at 150k.

After

/handoff writes a 25-line note, then /clear, then “Read @.claude/handoff.md and continue.” If you must stay: /compact keep the plan and failing tests.

From our runs: Run B planned in one session and built in a fresh one. Its context never passed 89k.
Rule 10

No unrequested docs

Before

IMPLEMENTATION_SUMMARY.md, CHANGES.md, NOTES_v2.md, and every MCP server ever installed, always on.

After

In CLAUDE.md: “Do not create markdown files unless asked.” Keep specs in docs/specs/, handoffs gitignored. Turn off MCP servers you aren't using.

From our runs: Run A rewrote docs/architecture.md and the seed script without being asked.

Replay

What surprised us

The Haiku switch didn't pay

Switching mid-session re-cached 53k tokens on the new model. Switch models when you clear, not halfway.

Small messages aren't small

“I'll go test” and “thanks!” each re-read 90k+ tokens. Cost depends on context size, not message length.

The spec predicts the corrections

Run B's only tweaks were things the spec didn't mention. What you leave out, you correct later.

Fix a prompt, 42 to 50 min

What would Claude have to guess?

“add search to the tickets page”

Rewrite it together. Three minutes.

Fix a prompt

One way to write it

Add a search box to the ticket list in @app/page.tsx. Match the query against title and description, case-insensitive, in listTickets in @lib/tickets/service.ts. Keep it in the URL as ?q= so it combines with the existing filters. Out of scope: full-text indexing, searching comments. Add tests next to the existing list tests. Plan first, no code.

Live: run both prompts in plan mode in TicketDesk and compare the plans and /context.

Fix a prompt

A good prompt has anti-goals

The prompt that started this session had

  • Purpose and audience
  • Background and constraints
  • What is not to be done

It could have added

  • How the 25% would be measured
  • Which topics matter most
  • The deliverable format

Purpose, context, constraints, out of scope, done when. That's a spec, at any size.

Quick hits, 50 to 55 min

Quick hits (details in the guide)

Subagents

Good for keeping exploration out of your main context. Parallel agents multiply usage, so rarely worth it for routine work.

Skills and commands

Save prompts you repeat, like /handoff. Skills only load fully when used.

Architecture map

One page, linked from CLAUDE.md. Gets most of the value of a code graph, and doesn't go stale.

Markdown piles

Specs in docs/specs/, handoffs gitignored, delete the rest. Old notes get read back in.

MCP servers

Their tool descriptions ride along on every message. Turn off the ones this task doesn't need.

/compact

Only when you can't clear. Tell it what to keep: “keep the plan and failing tests”.

Pick three, 55 to 60 min

Pick three for this week

Choose three rules and use them on everything for a week. The cheat sheet in the repo has all ten on one page.

If you can't decide: rules 1, 2 and 7. They made the biggest difference in our comparison.

Measure it

Note your session and weekly usage % at the start and end of each day, this week and next. Run /cost before you clear a big session. We'll compare as a team in two weeks.
